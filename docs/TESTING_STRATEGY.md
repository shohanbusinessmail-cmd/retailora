# Test strategy

Test money, discount/tax allocations, quantity conversion, moving average, reversals, returns, payment allocation, journal balancing, historical costs and profit with boundary/property cases. Real SQLite integration tests must verify transactions, foreign keys, locking, duplicate submissions, rollback, migrations, WAL-safe backup and restore. Scenario tests should cover cash/credit sales, collections, credit purchases, both return types, expenses, audit and reports reconciled to ledgers. Security tests cover auth/permissions, signatures/tampering, generator separation, key exclusion and file handling. Perform actual Windows UI, keyboard, Bengali font/PDF and printer tests, clean installation, upgrade, uninstall and offline end-to-end tests. Simulate crash, lock, disk exhaustion, invalid backups and interrupted migration; record reproducible results. Benchmark synthetic datasets at 1k/10k/100k products and 100k transactions with hardware and measurements documented. No artificial limits.

The current dependency-free domain smoke test is an initial harness, not an industry-standard full suite and has not been run here. CI currently lacks format verification, security scans, integration/UI suites and results publishing. Add gates as implementation exists; do not hide failures or treat a green build as commercial approval.
