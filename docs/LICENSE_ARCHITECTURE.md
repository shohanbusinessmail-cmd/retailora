# Offline licensing — proposed, not implemented

Customer executable must contain public verification keys only. An independent owner-only generator uses an external encrypted private key, not repository, customer installer, CI secrets or executable. Use ECDSA P-256/SHA-256 with strict encoding and a versioned, deterministic signed byte representation, product ID, key ID, unique license ID, business identity, issue timestamp, lifetime type and machine binding. Validate exact schema, supported algorithms/key IDs, signature and binding before any protected business operation; no algorithm negotiation from untrusted input. Key provisioning and embedded trusted public-key rotation require explicit owner procedure and security review before shipping.

Offline request export -> owner checks identity/entitlement -> generator signs -> customer imports -> local signature/product/machine/identity checks -> securely stored activation. Provide clear Bengali errors without secret disclosure. Windows stable machine identifiers with privacy-preserving derived binding and documented tolerance/reissue must be studied; avoid MAC-only identity. No hardware fingerprint approach can make copying impossible or guarantee survival of reinstalls. A lifetime license allows owner-authorized replacement on repair/reinstall/transfer; explain manual proof and reissue procedures, not forced renewals.

Generator keys should be encrypted at rest, protected by an owner-controlled password and/or Windows DPAPI/key store, with access control, protected independent offline backups and a tested recovery/rotation procedure. DPAPI tied to a user or machine alone is not a portable disaster recovery backup. Record issuance/transfer locally without sensitive contents in logs. Offline revocation records are advisory until a future signed update is manually imported; an offline installation cannot instantly learn a remote revocation. No generator, key management, validation or revocation is currently implemented. A copied executable must not suffice to sign.
